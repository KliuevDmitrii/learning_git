# RateBot

Бот следит за USD/GEL через APIlayer Exchange Rates Data и отправляет уведомления в Telegram при изменении курса. Значения курса и разницы округляются до трёх знаков после запятой: `2.594184 → 2.594`, `2.5945 → 2.595`. Сравниваются округлённые значения: изменение только четвёртого знака без изменения третьего не вызывает уведомления.

Основной запуск — GitHub Actions три раза в сутки по прежнему расписанию: **07:00, 10:00 и 12:30 UTC**, то есть **11:00, 14:00 и 16:30 по Тбилиси**. Каждый запуск выполняет одну проверку (`--once`) и сохраняет последний отправленный курс. Расписание работает в основной ветке после отправки изменений на GitHub; запуски могут задерживаться на стороне GitHub Actions. Отдельный постоянно работающий сервер для этого режима не нужен.

## Установка

```bash
cd learning_git/project
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В облачной среде проект находится в `/workspace/learning_git/project`, виртуальное окружение уже создано.

Для запусков GitHub Actions задайте Repository Secrets; при локальном запуске передайте через окружение процесса:

- `APILAYER_API_KEY` — ключ [Exchange Rates Data API](https://apilayer.com/marketplace/exchangerates_data-api).
- `TELEGRAM_TOKEN` — токен Telegram-бота.
- `TELEGRAM_CHAT_ID` — получатель уведомлений.

Также поддерживается локальный `project/data.json` (исключён из Git):

```json
{
  "access_key": "<ключ APIlayer>",
  "TELEGRAM": {
    "TOKEN": "<токен Telegram>",
    "CHAT_ID": "<ID чата>"
  }
}
```

Переменные окружения имеют приоритет. Для APIlayer ключ передаётся в заголовке `apikey`; ключ от другого сервиса не подходит.

## Дополнительно: непрерывный мониторинг

Этот режим запускается отдельно вручную. Для трёх проверок в сутки достаточно расписания GitHub Actions выше.

В `config.ini`:

```ini
[exchange]
url_base = https://api.apilayer.com/exchangerates_data/latest
base_currency = USD
target_currency = GEL
poll_interval_seconds = 60

[telegram]
url_telegram = https://api.telegram.org/bot
```

```bash
python exchange_rate.py
```

Бот сразу проверяет курс, затем делает паузу `poll_interval_seconds` между проверками. Остановка — `Ctrl+C`. На первом запуске без сохранённого курса отправляется одно сообщение; далее — только при изменении округлённого курса. Пороговые параметры `threshold` и `min_threshold` в старой конфигурации не используются.

При сетевой ошибке бот пишет её в журнал и повторяет попытку на следующем цикле. Последний курс сохраняется только после подтверждения Telegram; ошибки получения курса не вызывают поток сообщений в чат. При неоднозначном сетевом сбое после доставки сообщение может повториться: Telegram не предоставляет этому методу ключ дедупликации.

Частота реальных данных зависит от тарифа APIlayer и доступности пары USD/GEL. Выберите тариф с минутными обновлениями и достаточной квотой: опрос раз в минуту — до 43 200 запросов за 30 суток. Частый опрос не ускоряет обновление данных поставщиком. Уведомление появляется после очередной проверки и доставки Telegram; это не поток биржевых тиков. Проверьте актуальные условия поставщика перед включением мониторинга.

По умолчанию состояние хранится в `project/last_rate.json`; старое числовое значение читается и округляется автоматически. Можно задать отдельный постоянный файл:

```bash
python exchange_rate.py --state-file /path/to/state/last_rate.json
```

Запускайте один экземпляр для одной валютной пары и файла состояния. При смене пары используйте отдельный файл. Для проверки без цикла:

```bash
python exchange_rate.py --once
```

## Дополнительно: работа непрерывного мониторинга круглосуточно

Нужен постоянно работающий сервер с доступом по HTTPS к `api.apilayer.com` и `api.telegram.org`. Процесс текущей облачной задачи не обеспечивает круглосуточный запуск.

В `ratebot.service` есть пример systemd-сервиса для копии проекта в `/opt/ratebot/project`, виртуального окружения `.venv` и системного пользователя `ratebot`. Настройте эти пути и права под сервер. Передайте три переменные в защищённом `/etc/ratebot.env` (формат `NAME=value`, права `600`, владелец root), установите unit в `/etc/systemd/system/ratebot.service`, затем выполните:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ratebot
sudo journalctl -u ratebot -f
```

systemd хранит состояние в `/var/lib/ratebot/last_rate.json` и перезапускает процесс после сбоя. Убедитесь по журналу и полученному сообщению, что первая проверка и доставка прошли.

GitHub Actions выполняет тесты при изменениях кода. Запуски по расписанию и ручной `workflow_dispatch` делают один запрос с `--once`, используя одноимённые GitHub Secrets, и сохраняют курс в репозиторий. Не включайте непрерывный серверный бот одновременно с расписанием: у них независимое состояние и возможны повторные сообщения.

## Проверки

Из корня репозитория:

```bash
project/.venv/bin/python -m unittest discover -s project -p 'test_*.py' -v
```

Проверяются округление, изменение курса, повтор после сбоя доставки, ответы API и непрерывный цикл. В тестах сетевые вызовы заменены имитацией; они не расходуют квоту и не отправляют сообщения.
